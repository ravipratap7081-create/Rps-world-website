4 · Payment implementation plan

Design only — no checkout implemented, no Razorpay contact, appeal 21343834 untouched. Full doc: preview-work/payment-design.md; untested sketches: preview-work/payment-sketch/

  1. Buyer clicks buy → server-side API route creates Razorpay Order (amount fixed server-side; secret never leaves server) → browser gets only public key_id + order_id.
  2. Razorpay Checkout.js modal handles payment; card/UPI fields never touch Pro Universe code.
  3. Server verifies: signature check + direct payment-status fetch from Razorpay API (status=captured, amount, currency, order_id all match). Client callback is untrusted.
  4. Webhook (HMAC-SHA256, idempotent handlers) as async safety net.
  5. Only after verified payment: single-purpose signed 24h download URL streamed from a private bucket — never a static link; one order_id = one grant, replays can't double-unlock.

Env vars needed: RAZORPAY_KEY_ID, RAZORPAY_KEY_SECRET, RAZORPAY_WEBHOOK_SECRET, DOWNLOAD_SIGNING_SECRET — all server-side only. Explicitly out of scope until appeal resolves + approval: live keys, test transactions, wired checkout UI.
